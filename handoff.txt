REGMONTHLY DATE-ONLY MAIN DASHBOARD FIX
Date: 2026-08-24

Goal implemented
- Main dashboard: an actual article/review/document qualifies by publication/review date in the RegMonthly window. No relevance/title/quarterly/enforcement qualification is applied to the main dataset.
- Smart 100 JSON: remains the relevance/filtering layer.

Root causes found and fixed
1. Main dataset was globally running exclude_quarterly(). Removed that call; quarterly is now filtered only in Smart 100.
2. Same-source, same-day normalized-title dedupe could drop a distinct article at a different URL. Removed title-based dedupe. Main dedupe now collapses only true same-source canonical-URL duplicates plus non-article landing/navigation pages.
3. Date extraction did not support day-month-year dates such as "16 July 2026". Added DMY support.
4. FATF pages can contain unrelated dated links before the article content. Added FATF article-region date confirmation and forced detail-date confirmation for captured FATF items.
5. BIS was not registered. Added the official BIS entire-site RSS feed.
6. FATF was not registered. Added FATF News and Publications collection plus dashboard source mapping.
7. RegInfo.gov was not registered. Added its official EO 12866 XML feeds for pending reviews and completed YTD reviews, with dated records mapped to a new Regulatory Review tile.
8. Federal Register was pre-filtered by banking topics/agencies before it reached the main dashboard. Added an all-documents date-window API pull. Optional agency/type tags remain for UI filtering.
9. Federal Register and RegInfo.gov base Smart weights were lowered so the much broader main feed does not automatically crowd Smart 100 with unrelated records.

Validation performed
- Python syntax compilation passed.
- Dashboard inline JavaScript syntax passed node --check.
- Logic smoke tests passed for:
  * DMY and MDY date parsing
  * distinct same-title/same-day URLs both surviving main dedupe
  * tracking-parameter duplicate URL collapsing to one
  * quarterly item staying on main but being removed from Smart
  * RegInfo XML record parsing
  * Federal Register request containing only date conditions, not topic/agency/section/term qualification
  * FATF article date winning over an unrelated older header date

Important
The generated docs/data/*.json files in this ZIP are the prior snapshot. This sandbox cannot run the live network build end-to-end. After replacing/pushing these files, run the existing GitHub Actions workflow "Monthly Build" with workflow_dispatch. It already sets FORCE_RUN=1 and installs the required dependencies. That rebuild will populate BIS, FATF, RegInfo.gov, the unfiltered Federal Register date-window data, and all other sources into the generated site files.

BIS + REGINFO FOLLOW-UP FIX
Date: 2026-08-24

Why both new tiles could still be empty
1. BIS: the official "Entire BIS website" RSS feed is a rolling recent-items feed, not a reliable prior-month archive. A late-August manual rebuild can therefore see no July records even though BIS published many July items.
2. RegInfo.gov: the first XML parser expected a narrow set of direct-child XML tag names. RegInfo's machine-readable reports can use different/nested names, causing valid reviews to be missed.
3. RegInfo.gov dedupe: when a review had no rrid, every record fell back to the same eoPackageMain URL. Main-dashboard same-URL dedupe could then collapse multiple legitimate reviews.

Changes in this follow-up
- BIS now keeps the official RSS feed but also uses BIS's year-scoped official sitemap (sitemap.xml?documents=YYYY) as the prior-month archive/backfill.
- BIS sitemap dates are discovery hints only. Each candidate page must still expose an actual publication date inside the RegMonthly date window before inclusion.
- Added BIS-specific official feeds for press releases, central-bank speeches, BIS-management speeches, statistics, and research as additive sources.
- BIS detail pages use browser-style request headers to reduce false empty fetches.
- RegInfo XML parsing now tolerates nested/renamed fields and XML attributes using fuzzy field matching for title, RIN, agency, received date, concluded date, stage, action, and review ID.
- Added the RegInfo completed-last-30-days XML as an additive daily backup to Completed YTD.
- RegInfo fallback links are now RIN-specific and include a date/mode token so valid reviews do not collapse under URL dedupe when rrid is unavailable.
- RegInfo/BIS byte fetches now use browser-style XML/RSS request headers.

Validation performed
- python -m py_compile passed.
- Synthetic RegInfo tests passed for alternate field names, nested records, rrid and no-rrid cases.
- Two RegInfo reviews with different RINs and the same date survive main URL dedupe.
- Synthetic BIS year-sitemap test correctly excluded an old speech and included three target-month BIS records based on confirmed detail-page dates.
